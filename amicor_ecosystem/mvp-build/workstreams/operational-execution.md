# Operational Execution (MVP)

## Objective

Define the run model, staffing responsibilities, and execution cadence for launch operations.

## Operating Model

- Dispatch lead: queue health, assignment SLA compliance
- Dispatch coordinators: assignment execution and exception handling
- Partner success lead: provider communication and issue follow-up
- Finance ops: payout review and settlement tracking
- Product/engineering: workflow reliability and issue remediation

## Daily Execution Rhythm

1. Start-of-day readiness check
- Driver availability and coverage windows
- Open exceptions and unresolved escalations

2. In-day operations
- Active queue monitoring
- Assignment and reassignment actions
- Exception triage and escalation

3. End-of-day closeout
- Exception reconciliation
- KPI snapshot review
- Next-day risk watchlist preparation

## Incident and Escalation Model

Severity levels:
- Sev-1: patient-impacting failure, no immediate transport path
- Sev-2: SLA breach risk with active mitigation
- Sev-3: non-critical workflow degradation

Escalation path:
- Dispatcher -> Dispatch Lead -> Operations Lead -> Technical On-Call

## Weekly Governance

- KPI review with operations and product
- Payout reconciliation review
- Partner feedback review and action log
- Backlog prioritization for operational improvements

## MVP Readiness Checks

- Staffing coverage by operating window is confirmed.
- Exception playbooks are documented and practiced.
- Reporting outputs are reviewed and usable by partner-facing teams.
- Go-live checklist is signed by operations, product, and finance leads.
